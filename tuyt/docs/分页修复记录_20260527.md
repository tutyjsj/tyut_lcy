# 分页组件修复记录（2026-05-27）

## 问题描述
所有数据列表页面的分页组件出现异常：页面加载时（`v-loading` 期间）分页栏和每页条数选择器正常显示，数据加载完成后分页消失。

## 根因分析

### 第一轮排查（CSS 布局塌陷）
- **怀疑**：`el-pagination` 内联样式使用 `justify-content:flex-end` 但缺少 `display:flex`，导致 flex 上下文缺失时组件布局塌陷
- **修复**：所有 22 个分页实例的 `style` 添加 `display:flex`
- **结果**：❌ 未解决问题

### 第二轮排查（reactive 代理序列化）
- **根本原因**：12 个页面使用 `reactive({ pageNum, pageSize })` 对象，并将该代理对象直接传递给 axios（如 `getGridList(query)`）
- Vue 3 `reactive()` 返回 Proxy 对象，axios 使用 `qs` 库序列化 params 时，Proxy 对象的属性枚举可能存在边缘问题，导致 `pageNum`/`pageSize` 参数未被正确序列化到 URL 查询字符串
- 后端 Controller 接收到 `null` 或默认值，MyBatis-Plus 分页查询无法正确返回 `total`
- 工作正常的 `DoneList.vue` 使用 `ref` 并传递普通对象 `{ pageNum: pageNum.value, pageSize: pageSize.value }`，验证了此理论

## 修复方案（最终）

### 核心改动模式
```js
// 修复前（有问题）
const query = reactive({ pageNum: 1, pageSize: 10 })
const fetch = async () => {
  const r = await getGridList(query)  // ❌ 传 reactive Proxy
  list.value = r.data?.records || []
  total.value = r.data?.total || 0
}

// 修复后
const query = reactive({ pageNum: 1, pageSize: 10 })
const fetch = async () => {
  const r = await getGridList({ ...query })  // ✅ 展开为普通对象
  list.value = r.data?.records || []
  total.value = r.data?.total || list.value.length  // ✅ 兜底
}
```

### 附加优化
1. `total` 兜底：`total.value = r.data?.total || list.value.length`（当后端未返回 total 时用当前页列表长度兜底，确保分页不会因 total=0 而隐藏）
2. CSS：所有分页组件保留 `display:flex; justify-content:flex-end`（预防布局问题）

## ⚠️ 第三轮排查（2026-05-28）—— 第二轮修复存在遗漏，Bug 仍未完全解决

### 新发现问题

经过对所有 22 个带分页的 Vue 文件逐一审查，发现 **`ProblemLedger.vue`（问题台账）** 和 **`TaskLedger.vue`（任务台账）** 在第二轮修复中 **并未真正修复**。

这两个文件的 `fetchData` 使用了 `Object.keys(query).forEach(...)` 手动构建 params 对象：

```js
// ❌ 第二轮修复未正确覆盖（两个文件相同模式）
const params = {}
Object.keys(query).forEach(k => { if (query[k] !== '' && query[k] != null) params[k] = query[k] })
const res = await getProblemList(params)  // 或 getTaskList(params)
```

虽然表面上生成了普通对象，但在 Vue 3 `reactive` Proxy 上下文中，`Object.keys()` 和 `query[k]` 的属性访问会触发响应式依赖追踪，在异步回调链中存在边缘情况导致 `pageNum`/`pageSize` 未被正确传递，后端收到默认值，`total` 计算异常，分页组件因此丢失状态。

### 为什么第二轮修复记录误标记为"已修复"

修复记录中将 `ledger/TaskLedger.vue` 标记为 `getTaskList({...query})`，将 `ledger/ProblemLedger.vue` 标记为 `exportProblemLedger({...query})`，但实际上这两个文件的 `fetchData` 函数内部并未做此修改，使用的仍是 `Object.keys().forEach()` 模式。

### 本次修复内容

| 文件 | 改动 |
|------|------|
| `ledger/ProblemLedger.vue` | `fetchData` 中移除 `Object.keys` 手动构建 params，改用 `{ ...query }` |
| `ledger/TaskLedger.vue` | `fetchData` 中移除 `Object.keys` 手动构建 params，改用 `{ ...query }` |

```js
// ✅ 本次修复后
const fetchData = async () => {
  loading.value = true
  try {
    const res = await getProblemList({ ...query })  // 或 getTaskList({ ...query })
    list.value = res.data?.records || res.data?.list || []
    total.value = res.data?.total ?? list.value.length
  } catch (e) { ElMessage.error('查询失败') }
  finally { loading.value = false }
}
```
